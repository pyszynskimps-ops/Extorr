# Torrent Player 2.26 — saved sign-in details per website

Login identifiers and passwords entered in the website's own form are remembered when fields are committed or the form is submitted. Each HTTPS origin has its own record; expiring cookies, signing out, closing a browser window or restarting the application do not remove it. New login forms offer the remembered account. Selecting Use saved details fills the form; the website's submit and verification steps remain under user control. The native Login details editor provides masked prefilled fields, updates and Forget details. Remember login details can be disabled separately for each website.

Coverage includes external source browsers, the dedicated ExTorrent login window, first-party source acquisition and the shared 1337x browser. Existing encrypted native account entries are migrated only for the matching website. New manual website entries start being retained with this version. Imported source definitions and exported catalogue settings never contain saved passwords.

Production storage uses the existing AES-256-GCM SecureLoginStore and non-exportable Android Keystore keys in a separate namespace from sessions. Identifiers, passwords and their origin are encrypted; nonsensitive choices use hashed origin keys. The application's backups remain disabled. Explicit forgetting prevents legacy credentials from being silently reimported. Losing a device key discards unusable ciphertext rather than exposing its contents.

AndroidX WebKit 1.14.0 provides an origin-scoped web-message listener. The native main-frame flag, current top-level origin, document nonce and payload/type limits are checked before accepting a record. DOM listeners inspect only visible same-origin account forms; verification codes, hidden fields and card forms are excluded. Filling remembered values does not submit or recapture the form. On older WebView engines without the message-listener feature, the native editor can still save details for later proposals. Shared-browser callbacks are installed before navigation, with a bounded document refresh if an already loaded login page needs its message object.

Android 14 tests exercise encrypted preferences with a fixture-only AES key, independent websites, recreated stores, session logout, masked editing, opt-out, explicit forgetting, legacy migration, rejected source/frame/document messages and bridge cleanup/reopening. The production hardware Keystore adapter is the existing device implementation. Isolated Chromium fixtures verify trusted changes/submits, exact special-character filling, no submission during reuse, foreign-action/iframe rejection and registration username matching. No real account credentials or login requests are used. Physical-device installation is not exercised here.
